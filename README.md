## 目录怎么命名

一期视频一个目录，格式是：

```
<发布日期>-<中文主题词>

例：2026-09-29-MetaMuse
```

三条规则，以及为什么这么定：

**1. 日期用视频发布那天，格式 `YYYY-MM-DD`。**
这样目录列表天然按时间排好，永远不会乱，你也能对上"我大概是什么时候看的这期"。

> 视频里只会给出仓库地址，不会给某一期的具体链接。所以万一日期填错、或者发布推迟了，事后改名也不会让任何人的链接失效——从上面那张索引表进来，永远是对的。

**2. 主题词用中文，只用汉字、数字和字母。**
不要中文标点（全角的问号、冒号、逗号、书名号），也不要空格。这些在链接里会被编码成一长串百分号，有些工具还会误解析。

**3. 主题词取最有辨识度的那两三个词，不写完整标题。**
标题往往很长，发布后还可能微调。目录名只取你想起这期时脑子里冒出来的那个词。

### 每期目录里放什么

```
2026-09-29-MetaMuse/
├─ README.md      必须。本期要点 + 视频链接 + 最后核对日期
├─ 提示词/        有才建。只放视频里讲到的提示词，一个提示词一个文件，可以整段直接复制
├─ 模板/          有才建。任务书、检查清单这类可以照着填的东西
├─ 动效/          有才建。这期视频画面用的动效代码，能单独运行（见各期 动效/README.md）
└─ 出处.md        有才建。需要单独列出处时再写
```

README 每期都有，其余按需。**不要为了结构整齐去建空文件夹。**

`README.md` 必须保持这个名字，GitHub 靠它自动渲染每个目录的说明；其余文件用中文命名。

新开一期时，把 [`_template/`](_template/) 复制一份改个名就行。

### 文件命名

- 中文，同样不用标点和空格
- 一个文件只装一件事。提示词分开放，方便只复制需要的那一段
- 文件名写用途，不写日期（日期已经在上层目录里了）

## 关于这里的内容

- 标注为**官方**的，来自产品官方文档或帮助中心
- 标注为**实测**的，是我在自己账号里点出来的结果，可能受灰度、地区和套餐影响
- 标注为**媒体报道**的，没有官方确认，参考就好

这三类可信度不一样，引用时会分开标（有 `出处.md` 的期写在里面）。如果你发现哪条已经过时了，欢迎提 Issue。
