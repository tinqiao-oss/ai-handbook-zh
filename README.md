视频里提到的东西，在这里都能找到可以直接复制的版本。

**产品会变，文档会跟着改。** AI 工具的界面、模型和额度规则更新得很快，视频一旦发出去就固定在那个版本了，但这里的文档会持续更新。每期目录的 README 顶部都写着最后核对日期，改过什么记在 [CHANGELOG.md](CHANGELOG.md)。

## 目录怎么命名

一期视频一个目录，格式是：

```
<发布日期>-<英文主题词>

例：2026-08-15-chatgpt-usage
```

三条规则，以及为什么这么定：

**1. 日期用视频实际发布那天，格式 `YYYY-MM-DD`。**
这样目录列表天然按时间排好，永远不会乱；观众也能对上"我大概是什么时候看的这期"。

> ⚠️ **发布日期如果推迟了，必须在视频发出去之前把目录改名。**
> 链接一旦跟着视频发出去，就不能再动了，改名会让所有已发布的链接失效。所以顺序是：先定发布日期，再确认目录名，最后才发视频。

**2. 主题词用英文小写，单词之间用连字符。**
不用中文，因为中文目录名在链接里会变成一长串百分号编码，观众复制的时候很难看，有些工具处理起来也容易出问题。中文标题写在每期 README 的第一行和上面的索引表里，不会丢。

**3. 主题词取观众记得住的那个点，不写完整标题。**
标题往往很长，发布后还可能微调；目录名一旦发出去就不该再动。所以标题归标题，目录名只取最有辨识度的那两三个词——观众想起这期时脑子里冒出来的那个词，就是它。

### 每期目录里放什么

```
2026-08-11-chatgpt-usage/
├─ README.md      必须。本期要点 + 视频链接 + 最后核对日期
├─ sources.md     必须。每条关键结论的出处和核对日期
├─ prompts/       有提示词才建。一个提示词一个 .md，可以整段直接复制
└─ templates/     有模板才建。任务书、检查清单这类可以照着填的东西
```

前两个每期都有，后两个按需。**不要为了结构整齐去建空文件夹。**

新开一期时，把 [`_template/`](_template/) 复制一份改个名就行。

### 文件命名

- 全部小写，单词之间用连字符，例如 `task-brief.md`、`context-checklist.md`
- 一个文件只装一件事。提示词分开放，方便观众只复制他要的那一段
- 文件名写用途，不写期数（期数已经在上层目录里了）
